# 列表基线测量报告

测量对象：聊天消息列表（`lib/features/chat/messages_view.dart` 的 `ListView.builder`）与历史会话列表（`lib/features/sessions/session_drawer.dart` 的 `CustomScrollView` + `SliverList.builder`）。目标是拿到决策所需的现状数字，不修改产品代码。

## 结论摘要

1. **打开 1000 条消息的会话：首屏 2.0–5.6s，成本集中在单帧 1.6–4.5s 的 build**。同一测试内打开两条消息的对照会话只要 89–555ms。首屏慢不是滚动或流式造成的，而是打开时「跳到底部」让列表一次构建了大量消息项。
2. **滚动 1000 条消息本身构建便宜**：build p90 0.7–0.9ms、max 4.5–15ms；掉帧主要来自光栅化与重内容（raster p90 16–17ms，慢帧占比 9.5–16.6%）。
3. **流式输出期间滚动未见明显阻塞**：mock 以约 13 增量/秒推送 200 个增量，流式滚动窗口慢帧占比 0.4–11.2%，build p90 ≤0.8ms；偶发单帧 raster 达 233–241ms。真实服务端速率与长回复尚未覆盖。
4. **1000 个会话的抽屉**：打开（首行可见）106–247ms，完全展开 529–706ms；滚动慢帧占比 1.4–71.6%，三轮波动大，长尾明显。
5. **内存**：冷启动峰值 531–561MB（含播种与首次查询），打开长会话后 341–430MB，滚动与流式后 326–427MB；本次采样未见随滚动单调增长。

## 测量方法

- 测量入口：`integration_test/list_perf_test.dart`，用 `flutter drive --profile` 在真实渲染管线上驱动 App。
- 数据：测试内 `OPEN_CHAT_STRESS_SEED` 对应的压测样本（`lib/dev/mock_seed.dart` 的 `seedStressSamples`）：1 个 1000 条消息的长会话 + 1000 条会话；内容循环覆盖 Markdown 段落/图片链接、代码块、表格、mermaid、LaTeX。
- 帧耗时：`SchedulerBinding.instance.addTimingsCallback` 收集 `FrameTiming`，按场景切片统计 build、raster 与合计（build+raster）的 p50/p90/max；`slow_over_16_7_pct` = 合计 >16.7ms 的帧占比。
- 打开耗时：Stopwatch 计时，从点击会话行到目标消息组件进入树（长会话取最后一条消息的 `ValueKey`）。
- 内存：`ProcessInfo.currentRss`（MB）。
- 流式：`DeepSeekApiClient` 注入 `MockClient.streaming`，SSE 事件 25ms 一个、共 200 个增量；API Key 用测试替身覆盖。
- 每个场景连续 fling 10 次（聊天列表）或 10 次（抽屉），每次间隔 350ms。

## 解读

- **首屏的大头是「打开时跳到底部」**。`ChatMessageList` 布局后用 `jumpTo(maxScrollExtent)` 跟随底部（`messages_view.dart` 的 `_scheduleFollow`）；懒加载列表在未知总高度时跳到估算的最大偏移，会在一次布局中构建大量行。对照会话（2 条消息）没有这个成本，说明成本随消息数增长。
- **滚动成本与「是否虚拟化」无关**：`ListView.builder` 已懒构建，滚动 build 很便宜；掉帧来自可见内容的光栅化（mermaid/LaTeX/表格/图片链接）与偶发长帧。
- **流式期间的整页重建在当前 mock 速率下没有造成阻塞**。但这是 1000 条会话 + 约 13 增量/秒 + 单条短回复的结果；票 02 已从代码确认每个 SSE 事件会重建整页，频率或可见内容一升，成本按比例上升，需真实速率复测。
- **会话列表滚动波动大**（慢帧占比 1.4% / 71.6% / 67.2%），长尾明显；打开成本可接受。
- 内存没有随滚动单调增长的迹象，但只有三个采样点，不足以排除图片/图表缓存增长。

## 限制

- 模拟器 + 宿主 Metal，不是真机；绝对数字比真机乐观且波动大（同一场景首屏 2.0–5.6s）。决策应看相对关系与形状，不照抄绝对值。
- `flutter drive` 每次运行会清空应用数据：每轮都要重新播种（`seed_ms` 30–35s）。播种不计入首屏计时，但会抬高冷启动帧与 RSS 峰值。
- 流式为本地 mock：无网络抖动、无首 token 延迟、单条回复；不能代表真实 API 速率。
- 测试用 `tester.pump(16ms)` 驱动帧，实际帧节奏约 30–60fps；`slow_over_16_7_pct` 按 build+raster 计算，与 pump 节奏无关。

## 复现

```bash
# 1) 用宿主 GPU 启动模拟器（默认 auto 会回退 SwiftShader）
emulator -avd Medium_Phone_API_37.0 -gpu host -no-snapshot-load

# 2) profile 模式跑测量（每次会重装并清空数据，自动重新播种）
flutter drive --profile -d emulator-5554 \
  --driver=test_driver/integration_test.dart \
  --target=integration_test/list_perf_test.dart
```

结果行以 `BASELINE ` 前缀输出。手动造数据：debug 启动时加 `--dart-define=OPEN_CHAT_STRESS_SEED=true`（仅写入一次，哈希不变时跳过）。
