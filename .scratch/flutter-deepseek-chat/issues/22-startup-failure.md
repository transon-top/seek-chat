# 启动失败的错误界面

Type: grilling
Status: open

## Question

票 11 汇总时发现启动失败只有行为原则、没有界面规格：

- `architecture.md` §2 把「启动失败的处理」交给 `api.md` 与票 10，但两者都没有覆盖；
- `data-model.md` §8 只规定「迁移失败进入可重试错误态，不自动清库」。

需要决定：

1. 启动顺序中哪些失败可降级、哪些必须阻塞：数据库打开失败、迁移失败、`SharedPreferences` 读取失败、附件孤儿清理失败。附件清理已定为不阻塞，其余是否沿用同一降级策略？
2. 应用级错误界面的形态：文案、重试、退出、是否提供「重置本地数据」危险入口（默认不自动清库，重置是否进入 v1）。
3. 错误落点：`main()` 捕获后渲染专用页面，还是进入 `ProviderScope` 后由应用壳展示；与首帧主题 / 语言偏好的关系。
4. 测试接缝：内存库 / 注入失败替身覆盖哪些路径。

产出：更新 `architecture.md` §2 与 `data-model.md` §8、`ui.md` 的错误界面小节、ARB 键与对应测试。
