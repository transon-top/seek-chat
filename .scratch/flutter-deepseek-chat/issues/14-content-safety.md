# 内容安全与图片审核

Type: grilling
Status: resolved
Blocked by: 05, 13

## Question

1. `safety_check: { level: 'high' }` 的启用范围；是否所有请求都开启。
2. `stop_reason: refusal` 与 `stop_details` 的展示与后续操作。
3. 图片审核：上传图片触发审核的时机、审核失败的提示、是否阻止发送。
4. 错误码与用户文案；与 429 / 400 的区分。
5. 隐私：审核涉及的数据发送范围；设置页是否需要说明。
6. 测试样例：正常、拒答、图片被拒、网络失败。

产出：`safety.md` 章节 + 拒答状态表。

## Answer

结论写入 [`safety.md`](../safety.md)。要点：

1. **`safety_check`**：所有消息请求恒 `{ level: 'high' }`（新建、重新生成、续写、自动标题同请求）；无开关；Files API 上传不触发审核，审核发生在消息请求的输入与输出。
2. **拒答**：按协议丢弃已下发的思考与正文，只留工具块；展示优先级为模板文本 > 图片审核文案（`stop_details.explanation` 非空）> 通用拒答文案；正文样式而非错误色；隐藏时间线、来源与「N 个网页」；不能续写、不能重新生成。
3. **图片审核**：服务端在发送消息时审核；图片未通过时以 `refusal` 结束并用 `explanation` 指出被拦截图片；客户端不预先拦截发送、不解析路径，只显示图片审核文案，由用户移除图片后重发。
4. **错误区分**：仅 `400 Content Exists Risk` 归为内容审核拒绝（不可重试）；429 仍是限流；其他 400、402、413、5xx 按既有条件处理。
5. **隐私**：审核在用户配置的 DeepSeek API 同一请求内完成，无新增数据接收方；v1 设置页不加独立隐私说明，设置页文案由票 18 / 20 收口。
6. **测试**：输出拒答、图片拒答、审核 400 在 `app_test.dart` 端到端覆盖；模板文本、文案映射在纯函数测试覆盖；429 与网络失败沿用既有文案映射/控制器测试。明细见 `safety.md` §6。
