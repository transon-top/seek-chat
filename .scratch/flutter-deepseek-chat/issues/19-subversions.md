# 子版本计划与 v1 验收标准

Type: grilling
Status: resolved
Blocked by: 11

## Question

把 v1 的 10 项功能切成可独立验收的子版本：

1. 优先级与依赖：哪些功能是后续功能的前置（如附件先于图片审核、Markdown 先于引用角标、数据模型先于导入导出）。
2. 子版本划分：每个版本的范围、验收标准、演示脚本。
3. v1 验收对照表：截图 10 项逐条映射到验收用例与测试步骤。
4. 风险与不确定性：外部 API 依赖、平台权限、性能门槛。
5. 发布顺序与回滚点；每版的可运行判定。

产出：`roadmap.md` + `spec.md` 的验收章节。

## Answer

产出 [`roadmap.md`](../roadmap.md)，并在 `spec.md` §10 增加 §10.1 子版本验收门槛、
同步 §11.1 与 §12。结论：

- 十项功能行为已实现；剩余工作切为 S1 输入区、S2 消息区、S3 设置、S4 启动失败界面
  （票 22）、S5 无障碍 / 响应式 / 文案、S6 真机 / 性能 / CI / v1 候选。
  S0 为已完成基线（主题与聊天壳，提交 `365c4b5`）。
- 依赖：S1 → S2 → S3；S4 可插入 S1–S3 之间、不晚于 S5；S5 依赖 S1–S4；S6 依赖 S5。
  已完成的跨功能前置（附件先于审核、Markdown 先于角标、数据模型先于导入导出等）
  记在路线图 §1.1。
- 每版公共门槛见路线图 §2；S0–S5 打 `v1.0.0-sN`、S6 打 `v1.0.0-rc.1` 作为回滚点。
- 发布顺序：子版本在 `v1-dev` 推进，S6 全绿后合并 `main` 并打 `v1.0.0`；
  schema 1 与归档格式 3 不变，回滚不涉及数据迁移。
- 风险强调：界面迁移回归、票 22 范围扩大、真机可用性、性能未达标、平台权限；
  长期风险仍以 `spec.md` §11.2 为准。
