# Open Chat v1 子版本路线图

票：`19-subversions`。状态：定稿（2026-11-19）。
依据：[`spec.md`](spec.md) §10–§11、[`ui.md`](ui.md) §9–§10、[`architecture.md`](architecture.md) §10–§12。
术语见根目录 [`GLOSSARY.md`](../../GLOSSARY.md)。

## 0. 结论

- 十项验收功能的行为与自动化测试已实现；主要剩余工作是 shadcn 界面迁移
  （`ui.md` §9 第 3–7 步）、启动失败界面（票 22）、真机验收与性能基准、发布前 CI。
- 切成 6 个子版本（S1–S6），每版可独立运行、可演示、可回滚；S0 为已完成基线。
- 主线一次只推进一个子版本；S4（启动失败界面）可插入 S1–S3 之间，但不晚于 S5 收口。
- v1 发布门槛 = S6 的十项验收全绿 + 跨项验收（`spec.md` §10）全绿 + 无 P0 缺陷。

### 1.2 剩余依赖

```text
S0 基线（主题 + 聊天壳）
 ├─ S1 输入区 ── S2 消息区 ── S3 设置
 ├─ S4 启动失败界面（可插入 S1–S3，不晚于 S5）
 └─ S5 无障碍 / 响应式 / 文案（依赖 S1–S4）
      └─ S6 真机验收 / 性能 / CI / v1 候选（依赖 S5）
```

优先级：

1. **P0（阻塞 v1 验收）**：S1–S3 界面迁移、S4 启动失败界面、S6 真机与跨项验收。
2. **P1（验收质量）**：S5 无障碍、响应式、文案收口。
3. **P2（发布前）**：S6 的 CI 与性能基准回填；正式品牌名。

界面迁移按屏幕推进（输入区 → 消息区 → 设置），每步只替换一层控件，
保留渲染包的 Material 桥接；不一次性重写。

## 2. 子版本

每版共同门槛：`flutter analyze` 与 `flutter test` 全绿；iOS 模拟器与 Android
模拟器均可构建、启动；演示脚本通过；此前已验收功能无 P0 回归。

### S0 基线：主题与聊天壳（已完成）

- 范围：`ShadApp` + `ShadThemeData`、聊天页根路由、会话抽屉、分组与新建 / 重命名 / 删除；
  功能行为（API、数据、Markdown、语音、附件、导入导出）已实现。
- 证据：提交 `365c4b5`；`ui.md` §9 第 1–2 步。
- 验收：`flutter analyze` 无问题；`flutter test` 全绿；抽屉分组与当前会话高亮可演示。
- 演示脚本：冷启动进入聊天页 → 打开抽屉看分组与当前会话高亮 → 新建会话 →
  重命名 → 删除 → 回到聊天页。
- 可运行判定：analyze / test 全绿；两个模拟器可启动并完成上述演示。
- 回滚点：标签 `v1.0.0-s0`（在本票提交后打）。

### S1 输入区迁移

- 范围：`Composer`、蓝色激活开关、附件条、语音按钮、发送 / 停止、无 Key 态；
  对应 `ui.md` §9 第 3 步与 §5.2。
- 验收标准：
  1. 开关激活为蓝底 + 蓝描边 + 蓝图标；未激活透明底 + 灰描边。
  2. 发送 / 停止随状态切换；生成中附件与开关禁用。
  3. 附件选择、上传进度、失败重试、移除按 `attachments.md` §7 呈现。
  4. 录音 / 转写 / 错误态按 `speech.md` §2–§3、§6 呈现；无 Key 时发送入口提示设置。
  5. 输入区 widget 测试覆盖开关、发送 / 停止、附件失败、语音态。
- 演示脚本：输入文字 → 发送 → 停止；切两个开关看蓝色激活；选图上传 / 移除；
  点麦克风录音、取消、转写插入；清空 Key 后点发送。
- 可运行判定：analyze / test 全绿；两个模拟器可发一条流式消息并停止。
- 回滚点：标签 `v1.0.0-s1`。

### S2 消息区迁移

- 范围：用户 / 助手消息、思考与工具时间线、分支切换、操作条、来源胶囊与抽屉、
  引用角标；对应 `ui.md` §9 第 4 步、§5.4–§5.6、§8。
- 验收标准：
  1. 助手正文通栏；用户消息右对齐浅灰气泡；宽屏内容最大 760。
  2. 思考块折叠与计时、工具行 `wip / done / failed` 状态符合 `search.md` §3–§4。
  3. 来源胶囊为站点图标叠加 + `N 个网页`，打开底部来源抽屉；角标点击外开。
  4. 分支切换、编辑、重新生成、继续生成、复制、朗读的启用 / 禁用态符合 `ui.md` §5.5。
  5. 拒答隐藏来源与操作，使用正文样式文案。
  6. 消息区 widget 测试覆盖上述关键态；既有 `reply_view_test`、`search` 相关测试不回归。
- 演示脚本：发一条带搜索的回答 → 展开思考、点来源胶囊、点角标；编辑提问并切版本；
  重新生成、继续生成；朗读首帧；发一条触发拒答的消息看隐藏项。
- 可运行判定：analyze / test 全绿；两个模拟器完成消息、分支、来源与朗读演示。
- 回滚点：标签 `v1.0.0-s2`。

### S3 设置迁移

- 范围：三段导航设置 Sheet、主题卡片、语言 / 所在地 / 音色 Sheet、Key Dialog、
  数据管理二级视图；对应 `ui.md` §9 第 5 步、§1.5、§5.9。
- 验收标准：
  1. 设置占屏 92%，三段导航切换正确；聊天页从抽屉底部进入。
  2. 主题三卡片即时生效；语言跟随系统 / 中 / 英即时生效；音色持久化。
  3. Key 校验成功 / 失败 / 清除；所在地选择与「不指定」符合 `user-metadata.md`。
  4. 导入选择 → 覆盖确认 → 不可关闭进度 → 行内成败；导出与删除全部对话同规格。
  5. 麦克风权限三态与「打开系统设置」入口正确。
  6. 设置相关 widget 测试更新并通过。
- 演示脚本：打开设置 → 切主题 → 切语言 → 选所在地 → 校验 Key → 导入 / 导出 /
  删除全部对话 → 查看麦克风权限态。
- 可运行判定：analyze / test 全绿；两个模拟器完成设置演示，重启后设置保留。
- 回滚点：标签 `v1.0.0-s3`。

### S4 启动失败界面（票 22）

- 范围：先关闭票 22（降级 / 阻塞策略、错误界面形态、错误落点、测试接缝），
  再按结论实现；更新 `architecture.md` §2、`data-model.md` §8、`ui.md` 错误界面小节与 ARB。
- 验收标准：
  1. 票 22 的四项决策全部落文档，验收标准以票 22 结论为准，不在此预设。
  2. 每条启动失败路径按决策实现：数据库打开、迁移、偏好读取、附件孤儿清理；
     阻塞路径进入错误界面，可降级路径不阻塞且失败只记日志。
  3. 错误界面的重试、主题与语言关系按票 22 结论执行；中 / 英 × 浅 / 深四组合正确。
  4. 注入失败替身覆盖上述所有路径；重试与恢复路径有测试。
  5. 不自动清库；本版不改数据库 schema 与归档格式。
- 演示脚本：按票 22 决定的故障注入方式注入数据库打开失败 → 出现决策规定的错误界面 →
  重试仍失败 → 修复后重试进入聊天；偏好读取失败路径同法演示。
- 可运行判定：analyze / test 全绿；两个模拟器均可按票 22 的注入方式复现错误界面与重试。
- 回滚点：标签 `v1.0.0-s4`；本版不改变数据库 schema 与归档格式，回滚无数据影响。

### S5 无障碍、响应式与文案收口

- 范围：语义标签、动态字体 2.0、320 宽、横屏、平板、减少动画；新增 ARB 键、
  同步中英、`flutter gen-l10n`；补会话重命名 / 删除 widget 测试（`spec.md` §10 #4 缺口）；
  对应 `ui.md` §9 第 6–7 步。
- 验收标准：
  1. `ui.md` §10.1 无障碍项全过：关键语义标签、动态字体 2.0 无溢出、减少动画、320 宽。
  2. 四组合（中 / 英 × 浅 / 深）逐页无硬编码中文、无主题闪烁。
  3. 横屏与平板单列布局正确；点击区 ≥ 44。
  4. `flutter gen-l10n` 生成物入库；ARB 中英键一致。
  5. 会话重命名 / 删除 widget 测试补齐并通过。
- 演示脚本：字体调到 2.0 走聊天、抽屉、设置；320 宽设备 / 窗口；横屏与平板；
  打开减少动画；VoiceOver / TalkBack 过一遍聊天与设置。
- 可运行判定：analyze / test 全绿；两个模拟器四组合截图检查通过。
- 回滚点：标签 `v1.0.0-s5`。

### S6 真机验收、性能基准与 v1 候选

- 范围：iPhone 13 / Pixel 6 性能基准回填 `spec.md` §5.4；语音真机项（TTS 字节序、
  录音后立即朗读、来电 / 后台中断、Android 中断兜底）；文件选择 / 保存面板；
  GitHub Actions 执行生成、analyze、test；正式品牌名定稿；v1 候选构建。
- 验收标准：
  1. `spec.md` §10 十项验收与四条跨项验收全部通过，状态列改为「已实现」。
  2. 性能实测达标并回填：更新节流 50 ms–2 s、单帧 ≤ 16.7 ms、200 条消息流畅。
  3. 语音与附件的真机项全过；TTS 字节序经已知 PCM 验证。
  4. CI 在 `v1-dev` 执行 `build_runner`、`gen-l10n`、`analyze`、`test` 并绿；
     `v1-dev` 合并 `main` 后再跑一次并绿。
  5. 无 P0 缺陷；票 22 已关闭；品牌名与版本号定稿。
- 演示脚本：在两台真机按 `ui.md` §10.2 与 `speech.md` §11.2 全量走查一遍，

- 回滚点：标签 `v1.0.0-rc.1`；验收失败回退到最近通过的子版本标签，

## 4. 风险与不确定性

`spec.md` §11.2 的长期风险继续有效；本路线图新增或强调：

| 风险 | 影响 | 处置 |
| --- | --- | --- |
| 界面迁移引入行为回归 | 中 | 每版按屏幕 widget 测试 + 演示脚本；行为测试不删只改 |
| 票 22 结论扩大为启动架构重写 | 中 | 先锁四项决策，再实现；超出则拆新票，不阻塞 S1–S3 |
| 真机 / 模拟器不可用导致验收延期 | 中 | S6 前两周检查设备；模拟器项先行 |
| 性能目标未达标 | 中 | 回退 S2 局部渲染策略；保留节流与分段缓存两个调节点 |
| 麦克风 / 文件面板权限与真机差异 | 中 | S1、S3 覆盖拒绝态与跳系统设置；S6 真机复验 |

## 5. 发布顺序与回滚

1. 顺序：S1 → S2 → S3 →（S4 可插入 S1–S3 之间）→ S5 → S6；每版完成即打标签
   （S0–S5 为 `v1.0.0-sN`，S6 为 `v1.0.0-rc.1`），标签在 `v1-dev`。
2. 合并：S6 验收通过后 `v1-dev` 合并 `main`，打 `v1.0.0`；不在子版本中途合并。
3. 回滚：任一步失败，`git revert` 该版提交或回到上一标签；v1 各子版本数据库
   `schemaVersion` 为 1、归档格式为 3，回滚不涉及数据迁移；Key、设置与导出包不受影响。
   `sidebar-search`（[规格](../sidebar-search/spec.md)）把 `schemaVersion` 升到 2；
   该版之后回滚到 schema 1 需保留新库或重新导入归档，drift 不提供降级。
4. 每版必须同时满足 §2 的公共门槛（analyze / test、双模拟器、演示脚本、无 P0 回归），
   缺一不算「可运行」。
