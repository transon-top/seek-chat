# SeekChat 功能规格

本目录是 SeekChat **已实现功能**的行为规格，面向迭代维护：描述用户可见行为、
状态规则、边界与错误、持久化与兼容性，不写代码路径。

状态：维护中 · 最后核对：2026-11-23
适用：SeekChat `0.5.0+1` · 数据库 `schemaVersion 2` · 历史归档格式 `3`

## 1. 维护约定

- **代码为准。** 本文与实际代码冲突时，以代码行为为准；发现冲突应修正本文。
- **行为变更同步本文。** 修改已实现行为的同一个改动里更新对应文档与
  「最后核对」日期；不要先改文档再补代码。
- **新功能流程。** 新功能先在 `.scratch/<feature>/` 记录决策与票；实现完成、
  验收通过后，把稳定行为收敛到本目录，然后删除该 `.scratch` 目录。
  `.scratch` 保存进行中的决策，本目录保存已实现的行为。
- **术语。** 领域概念使用根目录 [`GLOSSARY.md`](../../GLOSSARY.md) 的词汇；
  架构决策见 [`docs/adr/`](../adr/)。
- **测试。** 每篇的「验证」只列测试文件名；新增行为应在对应测试文件补用例。

## 4. 通用约定

- 时间统一存 epoch 毫秒；界面按本地时区展示。
- 用户可见文案全部走 `gen_l10n` 的 ARB（`zh` / `en`）；模型正文不翻译。
- 错误文案的唯一映射点是 `lib/shared/error_text.dart`；服务端原始错误文本
  只在 debug 构建显示。
- Toast 颜色只由语义决定（`AppToastTone`：info / success / warning / error，
  见 `lib/shared/toast.dart`）；调用方传语义，不自行指定颜色。
- API Key 只存安全存储，不写数据库、不进日志、不进导出包。
- 日志只记录 debug 级诊断信息；不记录 Key、请求头、完整请求体与附件内容。
