# 按住说话与朗读

状态：已实现 · 最后核对：2026-11-23
适用：SeekChat `0.5.0+1`

## 1. 范围与入口

语音输入与朗读回答。语音输入采用「按住说话」；朗读入口只在 assistant 消息
操作条。

入口：

- 输入区操作行麦克风按钮：按住录音，松手转写。
- assistant 回复操作条朗读按钮：朗读正文，再次点击停止。
- 设置页「语音」区：麦克风权限状态与系统设置入口。

## 2. 行为与状态

### 2.1 语音输入状态机

运行状态：`idle`、`starting`、`recording`、`cancelling`、`transcribing`。
`error` 只作为失败提示的瞬态存在，提示结束回到 `idle`。

| 事件 | 行为 |
| --- | --- |
| 按下麦克风 | 收起键盘与附件面板，显示浮层骨架；单飞读取 Key、检查权限并启动录音 |
| 启动成功 | 进入 `recording`，显示波形；开始计时与电平回调 |
| 已松手但启动未返回 | 启动返回后立即取消，不转写、不提示 |
| 上滑 ≥ 80dp | 进入取消态，文案「松开取消」，一次中等触感 |
| 回拉 < 80dp | 恢复录音态，一次轻触感 |
| 松手（录音态） | 停止录音，进入转写，浮层保留并显示「识别中」 |
| 松手（取消态） | 丢弃录音，静默回到空闲 |
| 录音满 120 秒 | 自动停止并转写，提示已达到时长上限 |
| 来电 / 音频路由中断 / 进入后台 / 切会话 | 丢弃录音并取消转写；仅当前页可见时提示中断 |
| 首次系统授权弹窗 | 本次按住不开录；授权成功后提示「已授权麦克风，请再按住说话」 |
| 权限拒绝 / 无设备 / 启动失败 | 显示对应提示，回到空闲 |
| 录音中按系统返回 | 第一次只取消录音并留在聊天页 |

- 手势直接跟踪首个 pointer；取消阈值以按下瞬间的全局坐标为准，
  只判断纵向位移，可回拉，横向位移不取消。
- 录音规格：16-bit PCM WAV、16 kHz、单声道；上限 120 秒，
  客户端保证文件不超过 8 MiB。
- 录音、识别、取消共用同一动态浮层，覆盖输入卡与草稿行；
  录音与识别为蓝色，取消态整片转红，文案与波形同步变红。
- 录音与识别期间输入卡不可编辑，`+`、麦克风、发送与开关不可见、不可操作；
  识别中不提供取消入口。
- 无条件提供系统取消：切会话、离开页面、后台、页面销毁都会取消并丢弃。
- 无障碍路径使用语义 tap 切换开始 / 结束，并提供「取消录音」自定义动作。

### 2.2 转写与自动发送

- 转写请求：`POST /v1/tools/asr`，`Authorization: Bearer`，multipart 字段
  `file`，文件名 `recording.wav`。
- 返回 JSON 的 `text` 去首尾空白后：
  1. 先插入输入框当前光标处，替换选区，光标落在插入内容之后；
  2. 再按发送闸门尝试自动发送。
- 自动发送需要同时满足：有 API Key、当前没有生成中的回复、草稿附件全部完成、
  转写期间用户没有手动输入新文本。
- 任一条件不满足：只插入文本，并提示原因（无 Key / 生成中 / 附件上传中 /
  未自动发送）。转写结果永不丢失。
- 自动发送抛错：文本保留在输入框，提示「发送失败，已放入输入框」。
- 空转写或 `text` 为空：不插入，提示「未识别到内容」。
- 转写失败除权限、无设备、空结果与时长上限外，统一折叠为「语音识别失败」；
  不自动重试。

### 2.3 朗读

- 入口只在 assistant 操作条；输入区没有第二个朗读按钮。
- 可朗读条件：回复不在生成中、非拒答、正文非空。错误回复只要已有正文也可朗读。
- 朗读文本只取正文纯文本，不含思考、搜索步骤、引用角标、`[citation:N]`
  与模板文案；Markdown 清理由服务端 `filter_markdown` 完成。
- 状态：`idle`、`loading`、`playing`；没有暂停、进度与续传。
- 点击同一条：停止朗读；点击另一条：先停止当前，再开始新条。
- 全局只有一个音频通道；同一时间只朗读一条。
- 录音与朗读互斥；开始录音前先停止朗读，权限被拒绝时保持原朗读。
- 语音输入处于录音或转写时，朗读按钮置灰。
- 以下动作会停止朗读：发送、停止生成、继续生成、重新生成、切换会话、
  切换分支、离开聊天页、进入后台、音频焦点丢失。
- 请求：`POST /v1/tools/tts`，`voice_id` 取设置，`format: pcm`，
  `filter_markdown: true`；播放裸 PCM（s16le、24 kHz、单声道），
  首帧前缓冲 100 毫秒。
- 不截断文本；超过服务端字数或字节上限时返回 400，提示「这条回答暂时无法朗读」。
- 不缓存 TTS 音频，不写临时音频文件。

### 2.4 麦克风权限

- 唯一权限是麦克风；朗读不需要权限。
- 状态分为三种：
  - 未请求：尚未发起过系统权限请求；
  - 已允许；
  - 已拒绝 / 受限：显示提示与「打开系统设置」。
- 首次按住时请求权限；首次系统弹窗后本次手势不开录。
- iOS 拒绝后不会再次弹系统框；Android 可从系统设置返回后重新检查。
- 设置页只读展示三种状态，不提供应用内开关。

## 3. 边界与错误

- 录音权限拒绝 / 受限：提示并给出「打开系统设置」。
- 无输入设备或启动失败：对应提示。
- 空录音或空转写：提示未识别到内容。
- 达到 120 秒：提示时长上限，随后自动转写。
- 录音被来电、路由变化、后台或切页中断：提示录音已中断；转写取消无提示。
- ASR 的 400 / 401 / 402 / 408 / 413 / 429 / 503 / 504、网络失败、非 JSON、
  缺字段：统一按语音识别失败处理。
- TTS 400：这条回答暂时无法朗读；401 / 402 / 429 复用通用错误文案；
  其余 5xx、网络、空流与播放器错误提示朗读失败。
- 不自动重试；用户再次按住麦克风或再次点击朗读即可重试。
- 服务端原文不在 release 显示；debug 只写日志。

## 4. 持久化与兼容性

| 键 | 取值 | 默认 | 说明 |
| --- | --- | --- | --- |
| `tts.voice` | `stella` / `tide` | `stella` | 开始朗读时读取一次 |
| `speech.micRequested` | bool | `false` | 区分「未请求」与「已拒绝」 |

- 语音与音频不写数据库、不进历史归档、不做 TTS 缓存。
- 导入历史时保留设置与 Key，因此朗读音色不受导入影响。
- 不新增数据库表、迁移或归档字段。

## 5. 已知限制

- 只支持前台：不支持后台录音、后台朗读、锁屏控制或蓝牙远程控制。
- 不做实时流式识别与实时字幕；一次录音只在松手后转写。
- 首次授权后必须再次按住才能录音。
- 视频、音乐等外部音频占用可能中断录音；Android 的中断上报不完整，
  主要依赖应用生命周期兜底。
- 朗读没有暂停、进度、续播；离开页面即停止。
- 朗读文本超过服务端上限时无法朗读，客户端不截断。
- 部分音频后断流不能与正常结束区分，按失败处理，不静默播半截。
- 上滑取消在无障碍下没有等价手势；读屏用户使用语义 tap 与自定义动作。
