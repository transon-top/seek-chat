# 启动与失败恢复

状态：已实现 · 最后核对：2026-11-23
适用：SeekChat `0.5.0+1` · 数据库 `schemaVersion 2` · 归档格式 `3`

## 1. 范围与入口

冷启动时从进程开始到聊天页可用的整条链路，以及启动失败时的错误页、
重试与清除本地数据入口。运行期错误（会话列表加载失败、回复错误）不在此列。

入口：应用进程启动。

## 2. 启动顺序

1. 初始化 Flutter 绑定。
2. 读取 `SharedPreferences` 中的设置与偏好。
3. 打开数据库，把残留的 `pending` / `streaming` 回复统一置为 `stopped`
   （启动兜底，见[聊天与回复](chat/replies.md) §2.7）。
4. 写入 debug 样本（仅 debug 构建；压测样本需显式开启）。
5. 清理附件孤儿文件。
6. 渲染真实应用。

偏好读取先于数据库打开：数据库失败时错误页仍能沿用已存的主题与语言。

## 3. 失败分类

| 步骤 | 失败时 |
| --- | --- |
| 读取 `SharedPreferences` | 阻塞，进入启动失败页 |
| 打开数据库 / 迁移 | 阻塞，进入启动失败页 |
| 残留回复收尾 | 阻塞，进入启动失败页 |
| debug 样本写入 | 不阻塞，只写 debug 日志，继续启动 |
| 附件孤儿清理 | 不阻塞，只写 debug 日志，下次启动再试 |

- 错误页不经过 Riverpod 容器渲染；主题与语言直接取自失败时已读到的偏好，
  读取失败时用系统默认。
- 数据库迁移整体在一个事务中执行：中途失败回滚，schema version 不前进；
  同一库文件下次打开会重新尝试迁移。

## 4. 启动失败页

- 形态：错误图标、标题、说明、主按钮「重试」、危险按钮「清除本地会话与附件」；
  不设退出按钮。
- 页面不自动消失，直到重试成功或用户离开。
- debug 构建在说明后附原始异常文本；release 构建不显示。
- 主题与语言：
  - 偏好读取成功：沿用已存的 `ThemeMode` 与语言。
  - 偏好读取失败：主题跟随系统、语言由系统解析。

## 5. 重试

- 重试从头重跑整条启动链：关闭失败那次打开的数据库连接，新建数据库实例，
  重新读取偏好。不复用缓存的失败实例或失败结果。
- 成功后渲染真实应用；再次失败则刷新错误页上的异常信息，留在本页。

## 6. 清除本地数据

- 危险按钮点击后先二次确认；确认文案逐项写明删除与保留范围。
- 确认后先关闭数据库连接，再删除：
  - `seek_chat.sqlite` 及 `-journal` / `-wal` / `-shm`；
  - 旧库 `open_chat.sqlite` 及同套附属文件；
  - 应用支持目录下的 `attachments/` 整个目录。
- 保留：`SharedPreferences` 中的设置、安全存储中的 API Key。
- 不调用 Android `clearApplicationUserData()`。
- 删除成功后自动重试启动。
- 删除失败留在错误页并显示「清除失败，请重试。」；不自动重试、不自动再清库。
- 操作不承诺原子性：部分删除后再次执行会继续完成剩余删除。

## 7. 可访问性

- 全部文案走 ARB（`zh` / `en`）。
- 标题为语义 header；说明为 `liveRegion`。
- 按钮点击目标至少 48×48；按钮高度随文字生长。
- 文本对比度不低于 4.5:1。
- 系统字号放大到 200% 时内容换行、不截断，页面可滚动。

## 8. 边界与错误

- 迁移失败、数据库损坏等无法恢复的情况只提供人工重试与清除数据，
  不自动清库、不无限重试。
- 清除数据只覆盖本机会话与附件；远端 Files API 文件不删除。
- iOS 不提供程序化退出；本页不设退出按钮。
- 启动失败页不处理 Dart 尚未执行的原生启动崩溃。

## 9. 验证

- `test/app/startup_test.dart`：启动顺序、阻塞与非阻塞失败、失败页形态与
  主题/语言来源、重试、清除本地数据（删除范围、先关连接、设置保留、
  失败提示）、可访问性、迁移回滚与再次迁移成功。
